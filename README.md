# Product Analyst Trainer

Интерактивный тренажёр продуктового аналитика (Junior → Middle) с веткой по ML и Data Science. Карта навыков из пяти актов, теория с интерактивными виджетами, задачи с автопроверкой: SQL выполняется в браузере на DuckDB, Python (pandas, scipy, scikit-learn) — на Pyodide.

Все задачи решаются на одних синтетических данных — логах вымышленного сервиса доставки продуктов «Корзинка» за январь–июль 2024. В данные заложены истории, которые надо найти: A/B-тест с эффектом, эксперимент с SRM, поломка оплаты на Android, запуск бесплатной доставки в Казани.

## Что внутри

| Акт | Ветки |
|---|---|
| I. Фундамент | SQL (SELECT, агрегаты, JOIN), статистика (шум, описательные статистики, ДИ) |
| II. Продукт и метрики | оконные функции, когорты, воронки, DAU/MAU, retention, дерево метрик, ARPU/LTV/CAC |
| III. Эксперименты | гипотезы, критерии, дизайн A/B, мощность, SRM, подглядывание, множественные сравнения, ratio-метрики, CUPED, полный разбор теста |
| IV. Python, ML, DS | pandas, когорты в pandas, scipy; постановка ML-задачи, регрессии, метрики, валидация, бустинг; боковые ветки — DS-кейсы (отток, прогноз, uplift), причинность без A/B, визуализация |
| V. Аналитик целиком | разбор падения метрики, приоритизация, продуктовые кейсы, SQL- и статистический блиц |

Плюс:

- **испытания** в конце каждого акта;
- **тренажёр выбора метрик** — 11 продуктовых сценариев;
- **повторение** ошибок через 1, 3, 7, 14 дней;
- **песочница** для свободных SQL- и Python-запросов;
- уровни, звёзды, серии дней, экспорт и импорт прогресса.

## Запуск локально

Нужен только Python 3 (для локального сервера — браузер не даёт читать файлы курса по `file://`).

```bash
python tools/serve.py
```

Открыть http://localhost:8765.

## Публикация на GitHub Pages

Сборки нет — это статический сайт.

1. Создай репозиторий и залей в него содержимое папки.
2. Settings → Pages → Build and deployment → Source: **Deploy from a branch**, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет на `https://<логин>.github.io/<репозиторий>/`.

Файл `.nojekyll` уже лежит в корне, чтобы GitHub не обрабатывал сайт Jekyll-ом.

## Как устроено

```
index.html              точка входа, импорт-мапа библиотек (Preact, htm, KaTeX, js-yaml)
styles.css              стили, тёмная и светлая темы
app/
  main.js               роутинг и каркас
  content.js            загрузка курса и вычисление зависимостей между узлами
  store.js              прогресс в localStorage, опыт, повторение
  md.js                 мини-Markdown для уроков (+ формулы KaTeX и вставки виджетов)
  data/generate.js      генератор синтетических данных (детерминированный)
  engines/sql.js        DuckDB-wasm, сравнение результатов запросов
  engines/py.js         Pyodide, запуск и проверка Python-задач
  ui/                   страницы и компоненты
  widgets/              интерактивные виджеты уроков
content/
  course.yaml           акты, треки и испытания
  <ветка>.yaml          узлы ветки: теория, источники, задачи
  scenarios.yaml        сценарии тренажёра выбора метрик
tools/
  serve.py              локальный сервер без кеширования
  fix_yaml.py           починка типичной ошибки YAML (двоеточие в строке)
```

Библиотеки грузятся с jsDelivr с зафиксированными версиями. DuckDB (~35 МБ) и Pyodide (~10 МБ + пакеты) скачиваются при первом запуске задачи соответствующего типа и потом берутся из кеша браузера.

## Как добавить узел

1. Опиши узел в файле ветки `content/<ветка>.yaml`:

```yaml
  - id: sql.example
    title: Название
    summary: Одна строка под заголовком
    theory: |
      Markdown: ## заголовки, **жирный**, `код`, таблицы, списки, формулы $x^2$ и $$...$$.
      > [!tip] / [!warn] / [!key] / [!interview] — выноски
      ::widget power          # вставка виджета (список — в app/widgets/index.js)
    sources:
      - title: Название
        url: https://...
    tasks:
      - type: single          # один вариант; answer — индекс
        q: Вопрос
        options: [А, Б, В]
        answer: 1
        explain: Разбор
      - type: multi           # несколько вариантов; answer — список индексов
      - type: number          # answer — число; tol — относительная точность (по умолчанию 2%), atol — абсолютная
      - type: sql             # solution — эталон; ordered: true, если важен порядок строк
        tables: [orders]
        starter: |
          SELECT ...
        solution: |
          SELECT ...
      - type: python          # сравнивается переменная result с эталоном; test — своя проверка через assert
        packages: [scikit-learn]
        solution: |
          result = ...
```

2. Добавь id узла в нужный трек в `content/course.yaml`.
3. Открой `#/selftest` и нажми «Запустить» — страница выполнит все эталонные решения и покажет сломанные задачи.

Варианты ответов в квизах показываются в перемешанном (но стабильном) порядке, поэтому в разборах не ссылайся на «первый вариант» — называй вариант словами.

Если YAML не парсится из-за двоеточия внутри строки, запусти `python tools/fix_yaml.py content/*.yaml`.
